# OrthoStream

OrthoStream is an open-source cFS-based framework for real-time photogrammetric mapping from simulated UAV imagery, generating georeferenced dense point clouds, digital surface models, and incremental orthomosaics.

> **Project status:** Early-stage master's thesis research. The software architecture, interfaces, and experimental methodology are currently under development and may change as the research progresses.

## Overview

This project investigates the use of NASA's Core Flight System (cFS) as a modular software framework for real-time aerial photogrammetric mapping.

The system processes sequential aerial images generated by a UAV simulation environment together with:

- Image timestamps
- Known camera positions and orientations
- Camera intrinsic parameters
- Camera-to-body transformations
- Simulator-provided reference terrain or surface data

The planned processing pipeline incrementally generates:

- Georeferenced dense point clouds
- Digital surface models (DSMs)
- Orthorectified imagery
- Incremental orthomosaics

Camera poses are supplied directly by the simulator. Estimating the UAV or camera trajectory from imagery is outside the scope of this project.

## Research Objectives

The primary objectives of this research are to:

- Design a modular aerial mapping architecture based on independent cFS applications
- Synchronize simulated imagery with camera pose and calibration data
- Select suitable images according to overlap and viewing geometry
- Perform dense multi-view stereo reconstruction using known camera poses
- Transform reconstructed geometry into geographic coordinate systems
- Incrementally update DSM and orthomosaic products
- Measure mapping accuracy, processing latency, throughput, and resource usage
- Quantify the effects of camera position, orientation, and timing errors
- Evaluate the runtime overhead introduced by the cFS architecture
- Compare real-time results with an offline COLMAP reference workflow

## Planned Architecture

The mapping workflow is planned as a collection of independent cFS applications communicating through the cFE Software Bus.

| Application | Responsibility |
|---|---|
| `INGEST_APP` | Receives images, camera poses, timestamps, and calibration data from the data source |
| `ALIGN_APP` | Associates each image with the corresponding camera state |
| `SELECT_APP` | Selects keyframes and source views using overlap and viewing geometry |
| `DENSE_APP` | Computes depth maps with multi-view stereo |
| `GEOREF_APP` | Transforms depth maps into georeferenced points and writes the point cloud |
| `MAPPROD_APP` | Incrementally updates the DSM and orthomosaic |
| `RECORDER_APP` | Stores status, timing, and performance measurements |

See `docs/architecture_decisions/adr_012_application_boundaries.md`.

The Software Bus will primarily carry commands, metadata, status information, and references to large data objects. Images, depth maps, and point clouds will not necessarily be copied directly through Software Bus messages.

## Processing Pipeline

1. Receive an image and its timestamp from the simulator.
2. Associate the image with the corresponding camera pose.
3. Reject missing or temporally inconsistent data.
4. Correct camera lens distortion.
5. Estimate the geographic footprint of the image.
6. Select source images with suitable overlap and viewing geometry.
7. Generate depth maps using multi-view stereo.
8. Fuse depth observations into a dense point cloud.
9. Transform the point cloud into geographic coordinates.
10. Incrementally update the DSM and orthomosaic.
11. Record accuracy and performance measurements.

## Coordinate Systems

The project is expected to use the following coordinate systems:

- Camera coordinate frame
- UAV body coordinate frame
- Local East-North-Up (ENU) frame
- Earth-Centered, Earth-Fixed (ECEF) frame
- WGS 84 geodetic coordinates

The coordinate-frame definitions and transformation conventions will be documented before implementation of the georeferencing pipeline.

## Evaluation

The system will be evaluated using repeatable simulation scenarios with different:

- Flight altitudes
- Flight speeds
- Image overlap ratios
- Camera viewing angles
- Terrain types
- Image acquisition rates
- Camera position and orientation errors
- Timestamp offsets

Planned evaluation metrics include:

- Dense point-cloud accuracy and completeness
- DSM MAE, RMSE, and coverage
- Orthomosaic planimetric accuracy
- Map-update latency
- Image-processing throughput
- Map-update frequency
- Processing-queue length
- Dropped or skipped frame rate
- CPU, GPU, RAM, and GPU-memory usage
- cFE Software Bus latency and overhead

Results will be compared with the simulator reference surface and an offline COLMAP reconstruction.

## Building

OrthoStream is a cFS mission built against NASA cFS `v7.0.1`, which is included as a git submodule under `vendor/cfs` (see `docs/architecture_decisions/adr_009_cfs_version_and_build_structure.md`).

Third-party dependencies are pinned in `vcpkg.json` and built from source into `build-deps/`; nothing is installed system-wide (see `docs/architecture_decisions/adr_010_third_party_dependency_management.md`). System prerequisites are listed in `scripts/system-packages-ubuntu.txt`; COLMAP also needs the NVIDIA driver and the CUDA toolkit. On Ubuntu:

```bash
sudo apt install $(grep -v '^#' scripts/system-packages-ubuntu.txt)
```

```bash
git submodule update --init --recursive
scripts/setup_dependencies.sh                     # once; long first build (ORTHOSTREAM_WITH_COLMAP=0 skips COLMAP, ORTHOSTREAM_WITH_REFINE=0 skips GTSAM)
scripts/fetch_proj_grids.sh                       # once; PROJ grids with pinned checksums
scripts/build_libs.sh                             # algorithm libraries and their tests, without cFS
mission/build.sh                                  # debug build
ORTHOSTREAM_BUILD_TYPE=release mission/build.sh   # release build, used for all measurements
cd build/exe/cpu1 && ./core-cpu1
```

At this stage the mission runs the cFS lab applications only (SCH_LAB, CI_LAB, TO_LAB). The OrthoStream applications are added as the architecture decisions are implemented.

The OrthoStream applications and libraries are reusable cFS components. Another cFS mission can include them by adding `apps/` to its `CFS_APP_PATH`, listing the applications in its `targets.cmake`, and overriding their default configuration headers where needed. The mission under `mission/` is the reference configuration used for the thesis.
